# Tech Debt (ESP32 Remote)

Сюда складываем долги/косяки/риски и наблюдения, чтобы `Handoff.md` оставался “чистым” (текущее состояние + что делать дальше).

## 1) Git / репозиторий

### 1.1 GitHub limit > 100 MB (remote_src.tgz)
Симптом:
- push падает: `File remote_src.tgz is ... exceeds GitHub's file size limit of 100MB`

Решение:
- не коммитить большие архивы исходников
- добавить `remote_src.tgz` в `.gitignore`
- если уже в индексе: `git rm --cached remote_src.tgz`

Опция (если реально нужно хранить большие артефакты в git):
- Git LFS (осознанно и отдельно документировать политику)

## 2) ESP-IDF / драйверы

### 2.1 Warning: legacy I2C driver
Симптом в логах:
- `This driver is an old driver, please migrate ... driver/i2c_master.h`

Риск:
- со временем legacy API может стать проблемным при апдейтах/совместимости

План:
- миграция на новый `i2c_master` API в отдельной сессии, отдельным коммитом

## 3) Wireless / ESPNOW

### 3.1 ACK пока не участвует в UI state
Сейчас:
- ACK логируется, но не “цементирует” UI

Риск:
- UI может расходиться со “state of truth” лампы при потерях пакетов

План:
- привязать UI к ack/state_seq (single source of truth)
- добавить retry/timeout на CTRL

### 3.2 dst_node = broadcast
Сейчас:
- dst_node часто `0xFFFF` (broadcast)

План:
- перейти на unicast (когда адресация/registry будут готовы)

## 4) Storage / SD

### 4.1 Auto format при mount fail
Если включено `format_if_mount_failed = true`, есть риск автоформатирования карты при проблеме маунта.

План:
- для “продукта” отключить автоформат или поставить жёсткий флаг/меню подтверждения

## 5) Power key тайминги
Сейчас в Power-key ADR:
- пороги зависят от частоты вызова `PWR_Loop()` (итерационный счётчик)

Риск:
- изменение периодики меняет фактические секунды

План:
- перейти на ms-тайминги (pdMS_TO_TICKS / esp_timer), когда будем стабилизировать питание
