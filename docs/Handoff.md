# Handoff: ESP32 Remote (Touch LCD)

## 0) Коротко
Пульт на ESP32-S3 с круглым дисплеем 412x412 (SPD2010 QSPI) и тачем (SPD2010 I2C),
UI на LVGL, карусель экранов устройств, управление лампой по ESP-NOW.

## 1) Что сейчас работает (факты из кода и договорённостей)
- Экран (SPD2010) и подсветка (LEDC PWM на GPIO5). 
- Touch по I2C addr 0x53, INT GPIO4. 
- I2C на GPIO10/11 @ 400 kHz. 
- Драйверный цикл (IMU/RTC/BAT/PWR) в отдельном task. 
- Wi-Fi STA + ESPNOW: канал фиксируется, затем старт `j_espnow_link_start()`. 
- Device registry: Diag экран всегда последний, вставка новых экранов перед ним. 
- Оверлеи яркости/скорости закрываются с `ui_active_dev_set_overlay(false)` (важно для блокировки глобальных свайпов). 

UI сценарии (по текущей договорённости):
- Долгий тап верхняя дуга: overlay яркости (полный круг, старт справа).
- Долгий тап нижняя дуга: overlay скорости (полный круг, старт справа).
- Двойной тап центр: вход/выход в меню выбора анимаций.
- В меню анимаций: вертикальный свайп крутит колесо, горизонтальный вправо/влево меняет эффект на +1/-1.
- Долгий тап центр: power off лампы.
- Короткий тап: сейчас pause (TODO: пауза только по тапу в центр, не по любому тапу).
- Свайп влево/вправо: переключение device screen.

##  Wireless / ESPNOW (фактический статус)
- Wi-Fi STA поднимается, канал фиксируется: `CONFIG_J_WIFI_FALLBACK_CH`
- ESPNOW link:
  - peer MAC берётся из `CONFIG_J_ESPNOW_PEER_MAC`
  - CTRL команды отправляются
  - ACK принимается и логируется, но не влияет на UI state

---

##  UI архитектура (фактические правила)
- Устройства представлены как “драйверы экранов” (`create_root/destroy_root/on_enter/on_leave/refresh`)
- Есть per-device контекст (`stack_depth`, `overlay_depth`, brightness/speed и view modes)
- Правило: **Diag всегда последний**, новые устройства вставляются перед ним

---

##  Известные риски/заметки
- SD mount использует `format_if_mount_failed = true`:
  - при проблеме маунта карта может быть отформатирована автоматически
- Power key тайминги (`Device_Sleep_Time/Restart/Shutdown`) зависят от частоты вызова `PWR_Loop()` (это счётчик итераций)
