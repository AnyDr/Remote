# ADR-0002: UI — Device carousel + per-device context, global swipe blocking

## Context
Нужно масштабировать UI под несколько устройств (Lamp, HoneyComb, System/Diag и будущие),
при этом:
- не сломать жесты,
- не держать глобальные переменные на всё (иначе баги “переезжают” между экранами),
- иметь понятные правила навигации.

## Decision
- Каждое устройство представлено драйвером `j_dev_drv_t`:
  - `create_root/destroy_root`
  - `on_enter/on_leave/refresh` (опционально)
- Для каждого устройства есть контекст `j_dev_ctx`:
  - `stack_depth` — глубина локальных подэкранов
  - `overlay_depth` — число активных оверлеев
  - локальные UI параметры (brightness/speed, view modes)
- Глобальный свайп (переключение устройства) блокируется, если:
  - `stack_depth > 0` или `overlay_depth > 0`
- Правило карусели:
  - Diag/System экран всегда последний
  - новые устройства вставляются перед ним

## Consequences
Плюсы:
- UI масштабируется без монолита.
- Оверлеи и подэкраны не ломают глобальную навигацию.
- Состояние устройства не “протекает” в другое устройство.

Минусы/долги:
- Нужно дисциплинированно вести `stack_depth/overlay_depth` (инк/дек строго парно).
- Для “идеала” потребуется формализовать таблицу жестов и единый диспетчер событий.
